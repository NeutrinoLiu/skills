## Aug 24 — the build

- Brief, in shape: "make the video which is expected to be 5min long. it could be regarded as
  a small presentation. so i would like you do this step by step: first you design the cuts of
  the video, using a markdown file as your scratch book; then you implement html slides showing
  me each cut, with expected time to stay on this cut, together with script for each cut; then
  you generate/render all the assets you need for each cut, in the meantime you generate the
  audio for each cut with tts; finally assemble everything into a video. the html slides should
  be a checkpoint. get me involved at that time."
- `cuts.md`: four movements, sixteen cuts, the 480p rule written down first. The paper's
  system figure dropped for a four-box diagram. `build/cutdata.py` as the single source;
  `deck.py` → `deck.html` with a 480p toggle and `?cut=N` render mode.
- Checkpoint decisions: `edge-tts` (approved), voice Andrew at −4 % rate, subtitles as a
  sidecar, cut 11 rebuilt around the E-Rayzer reconstructions instead of two text cards.
- Renderers: `shots.py` (Chrome + DOM probe → `boxes.json`), `thumbs.py`, `tts.py` → mp3 +
  srt + `timing.json`. The first `shots.py` run took 55 minutes because Chrome would not exit;
  capped at 30 s per cut. Four result panels merged into one grey block on the first pass —
  `aspect-ratio + flex` taking width from the caption; fixed by sizing off `--vh`.
- `assemble.py`: per-cut overlay into probed boxes, concat, two-pass loudnorm to −16 LUFS.
  Verified: no overflow (the collision check itself tested by reverting a cut to the broken
  value), midpoint frames against slide PNGs (worst RMSE 1.18 %), speech onset +0.15 s on all
  16 cuts, a 480p read-through. Delivered 4:57.6, 52 MB.

## What made it work

1. **The four-step contract with a named checkpoint**, given by Bangya up front.
2. **One source (`cutdata.py`) and one file that is both checkpoint and render source.**
3. **The 480p rule written before the first slide.**
4. **Geometry read out of the DOM**, never hand-computed, with a probe that reports overflow.
5. **Measured narration sets the timings**, not the plan.
6. **Verification by numbers *and* by sampled frames from the final encode.**

## What hurt

- Captions took three rounds because the first two answers were the obvious ones (a sidecar,
  then a matte) rather than the one that costs layout (reserve the strip).
- Rotation was applied everywhere 3D appeared, then pulled back from things that are cached
  stills. The distinction is now a convention.
- Correspondence between condition and result was assumed, not built; `conds.py` should have
  existed from the start.
- Every Chrome and ffmpeg run that hung or died was an environment gotcha (updater, OOM,
  PEP 668) rather than a design problem — listed in `SKILL.md` so they cost nothing next time.
- Attribution for another paper's frames in the curriculum cut is still open, as on the poster.
